## 3. ◇ 데이터 분석

**소제목**: 베이스라인이 버리고 있던 신호를 정량으로 찾다

- **70,000건 전수 분석** → 신호 3원천 확인: 프롬프트 텍스트 · 행동 시퀀스 · 세션 메타
- 행동 전이 패턴 발견 — `write_file → edit_file` **40%**, `read_file → edit_file` 29%
  - 단, 직전 행동 **단독 정확도는 23%** → 텍스트와 **결합해야** 유효
- 실험으로 확인: 프롬프트만 **0.437** → 이력·메타 토큰 추가 **0.611** (**+0.17**)
- **누수 후보를 발견하고 실험으로 검증**
  - 같은 세션 다른 step의 history에 정답 존재 (train 커버 **86.6%**, 조회 정확도 **100%**)
  - 넣은 제출 = 뺀 제출 (점수 소수점 10자리까지 동일) → **평가 데이터 발동 0건 실증**
- **라벨 모호성 정량화**: 중복 발화 구간의 정확도 상한 약 **75%**
  → 후반 전략을 "더 큰 모델"이 아닌 **모호 구간의 마진 싸움**으로 전환한 근거

**이 칸의 시각 요소 (택 1)**
- 전이 확률 히트맵 (14×14) 축소판 — 가장 눈길을 끕니다
- 또는 클래스 분포 막대그래프 (9배 불균형이 한눈에 보임)

## 4. ◇ 모델 검증

**소제목**: 무엇을 믿을지 먼저 정했다

- **세션 분리 검증** — GroupShuffleSplit (세션 ID 기준, seed 42, val 14,106건)
  - 같은 세션이 학습·검증에 갈리면 점수가 부풀려짐 → 원천 차단
- **검증 → 리더보드 매핑 실측**: 초기 4연속 제출에서 **LB = 검증 + 0.005** 일관
  → 제출 없이도 채택·기각 가능 → 실험 속도 확보
- **축마다 신뢰 도구를 분리**
  - 차이 **> 0.003** (구조적 변경) → 로컬 검증으로 결정
  - 차이 **≤ 0.002** (가중치·온도) → 검증 노이즈, 소량 LB 프로브로 정점 탐색
- **과적합 3건을 조기에 검출·기각**

| 시도 | 검증 | 리더보드 | 조치 |
|---|---|---|---|
| 클래스별 scale 후처리 | ↑ | ↓ | 즉시 제거 (+0.0013 회복) |
| 41만 조합 전수 탐색 | **0.812** | **0.795** | 로컬-LB 상관 0.20 실측 후 기각 |
| 학습형 메타 게이트 | ↑ | **-0.005** | 잔존 누수 확인 후 전면 폐기 |

> 이 표는 포스터에서 **가장 설득력 있는 칸**입니다. 크기를 아끼지 마세요.

### 핵심 기여 ① ID토큰 직렬화 — **LB +0.011 (단일 기법 최대)**
- LightGBM의 **최강 피처가 세션 번호**였는데, 트랜스포머는 이를 전혀 보지 못하고 있었음

- 결과: 트랜스포머가 구조 신호를 흡수 → **LightGBM 가중치 0.4 → 0.10**

### 핵심 기여 ② 선택적 게이트 앙상블
- 모든 행에 모든 모델을 쓰지 않고, **두 모델이 갈리는 약 5%**에만 추가 모델 투입

- 부수 효과: 추가 모델이 5%에서만 동작 → **서버 10분 예산 절약**

## 6. ◇ 적용 가능성

> **포스터에서만 새로 쓰는 칸입니다.** 발표 자료에는 이 항목이 없으니 여기 문안을 그대로 쓰세요.
> 기업 관계자가 가장 관심 있게 보는 칸이기도 합니다.

**소제목**: 대회를 넘어 — 구조는 그대로 재사용된다

**① 제품 적용 — 예측한 다음 행동으로 체감 속도를 줄인다**
- 다음 행동을 미리 알면 **사전 로딩(prefetch)** 가능: `read_file` 예측 시 파일을 미리 읽어둠
- `edit_file`·`apply_patch`처럼 **되돌리기 어려운 행동**은 사전 확인 UI를 띄우는 안전장치
- IDE·에이전트의 **다음 액션 제안**(단축 버튼)으로 조작 단계 축소

**② 비용 최적화 — 게이트 앙상블은 캐스케이드 추론 그 자체**
- "쉬운 입력은 작은 모델, **어려운 입력에만 큰 모델**"은 LLM 서빙 비용의 핵심 패턴
- 본 구조는 **모델 간 불일치**를 난이도 신호로 사용 → 별도 난이도 판별기가 불필요
- 실측: 추가 모델 2개가 **5%의 입력에서만** 동작하면서 성능은 계단식 상승

**③ 운영 적용 — SLA가 있는 추론 파이프라인의 설계 원형**
- **시간예산(deadline) 기반 부분 처리** + **소스 단위 자동 재정규화**
- 모델 일부가 죽어도 남은 소스로 답이 나감 → 무중단 추론
- 대회 전 기간 **제출 실패 0회**로 실증

**④ 한계도 함께 명시 (신뢰를 만드는 문장)**
- ID토큰은 **본 데이터 생성 방식에 의존**하는 피처라 실제 서비스에는 일반화되지 않음
- 재사용 가능한 것은 **게이트 앙상블 구조 · 폴백 설계 · 검증 방법론**
